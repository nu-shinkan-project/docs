# デプロイ

クレデンシャルの窃盗リスクを抑えるため、デプロイはローカルでは行わず、GitHub Actions 上で行うことを基本とします。

CI/CD の設定により、開発者は主に次の操作によってデプロイをトリガーできます。

- GitHub への Push
- デプロイ用タグの付け替え

## デプロイ用タグ

このプロジェクトでは、`main` の最新コミットがそのまま各環境へデプロイされるとは限りません。

デプロイ対象は Git タグによって管理されています。

- `release`: 本番環境へデプロイするコミット
- `staging`: ステージング環境へデプロイするコミット

そのため、`main` の先頭と、実際に各環境へデプロイされているコミットが異なることがあります。

デプロイするコミットを変更したい場合は、対象となるタグを別のコミットへ付け替えます。

タグを付け替えるときは、GitHub の **Actions** タブから、タグの付け替えを行う workflow を探して実行します。

たとえば、本番環境で問題が発生した場合には、`release` タグを以前正常に動作していたコミットへ戻すことで、そのコミットを再び本番環境へデプロイできます。

この仕組みにより、Git の履歴そのものを変更することなく、デプロイ対象だけを切り替えられます。
