# Pull Request の運用

この文書では，メインリポジトリにおけるプルリクエストの運用方法を説明する．

## マージ方法の選び方

このプロジェクトでは、Pull Request のコミットを変更せずに `main` へ取り込むための `/merge-ff` という仕組みを用意している。

Pull Request に

`/merge-ff`

というコメントを投稿すると、GitHub Actions が Pull Request の状態を確認する。
fast-forward が可能であれば、その Pull Request のコミットがそのまま `main` に取り込まれる。

この方法では、新しい merge commit を作ったり、既存のコミットを書き換えたりしない。
レビューされたコミットそのものが、そのまま `main` の履歴になる。

`rebase` でも同様に `main` へ取り込むことはできるが、コミットハッシュが書き換わる。
そのため、マージ後もブランチを継続して利用する場合には、`/merge-ff` を利用すると扱いやすい。

また、作業中に `main` からのマージを行っている場合など、`rebase` では扱いにくい履歴であっても、fast-forward が可能であれば `/merge-ff` を利用できる。

一方、マージ後にブランチを継続して利用しない場合は、`squash` を利用してもよい。

## 作業ブランチ

作業ブランチの名前に特定のプレフィックスを付ける必要はない。

ただし、次のプレフィックスを使用したブランチは、`main` へのマージ後に自動的に削除される。

- `feature/*`: 通常の開発で、自動削除を利用したい場合
- `hotfix/*`: 緊急修正で、自動削除を利用したい場合

マージ後もブランチを残したい場合や、これらの分類に当てはまらない作業では、別の名前を使用できる。
