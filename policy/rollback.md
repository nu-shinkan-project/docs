# デプロイロールバック運用規約

この規約は、本番環境またはステージング環境で問題が発生し、デプロイ済みの状態を戻す必要がある場合の Git 運用を定める。

## 基本原則

ロールバックのためだけに `main` へ revert commit を追加してはならない。

デプロイ対象はタグによって管理し、問題発生時にはタグの付け替え、または `hotfix/*` ブランチによる緊急修正を利用する。

## 過去のコミットへ戻す場合

既知の正常なコミットへ戻すことで問題を回避できる場合は、対象環境のタグをそのコミットへ付け替える。

- 本番環境では `release`
- ステージング環境では `staging`

その後、通常の開発フローで `main` 上の問題を修正する。

ロールバックのために `main` 自体を過去の状態へ戻す必要はない。

## 緊急修正が必要な場合

過去のコミットへ戻すだけでは問題を解決できず、緊急修正が必要な場合は `hotfix/*` ブランチを作成する。

`hotfix/*` では、発生している問題を解消するために必要な変更だけを行う。

修正後は、必要なデプロイタグを hotfix 上のコミットへ付け替えることができる。

## hotfix 中の開発制限

`hotfix/*` は緊急対応のための一時的なブランチであり、通常の開発ブランチとして使用してはならない。

hotfix が必要となった問題への対応が完了するまで、その問題への対応以外の変更を `main` にマージしてはならない。

これは、hotfix と `main` の履歴が不要に分岐し、修正の取り込みが複雑になることを防ぐためである。

## hotfix を main に取り込む場合

hotfix で行った修正を `main` に取り込む必要がある場合は、`hotfix/*` ブランチから `main` へ Pull Request を作成する。

通常の変更と同様にレビューを受け、マージ可能な状態になったあと `/merge-ff` を使用して取り込む。

hotfix の内容をレビューなしで直接 `main` に反映してはならない。

## hotfix の終了

hotfix の内容が `main` に取り込まれ、通常のデプロイ経路へ復帰した時点で hotfix は終了する。

以降の開発を `hotfix/*` 上で継続してはならない。
