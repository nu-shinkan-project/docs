# Issue 運用規約

本文書は，メインリポジトリおよびドキュメントリポジトリにおけるIssueの運用方針を定める．

## 基本方針

Issue は、問題や提案を気軽に記録し、後から整理するために用いる。
情報や考えがまとまっていなくても作成してよい。作成後に、必要な情報を補い、ラベルで対応に必要な状態を示す。

## 作成とテンプレート

Issue の作成にあたり、所定のテンプレートや必須の記載項目は設けない。作成時の Type の設定やラベルの付与も必須としない。

機能提案や不具合報告などのために、Markdown 形式のテンプレートを提供してよい。テンプレートの利用および各項目の記入は任意とし、不要な項目は削除してよい。

## Draft と Ready

`ready` ラベルのない Issue は、draft として扱う。Draft は、作成者の手元の文脈に依存していてよく、他の人がそのまま着手できることを期待しない状態である。

作成者はこの前提で Issue を作成する。他の人が情報の補足や整理を手伝うことも妨げない。

他の人に割り当てて取り組んでもらえる程度に、目的・対象・完了の目安が整理されたら、`ready` を付与する。所定の見出しや書式は要求しない。

`ready` は、実装方法の確定を要求しない。調査を目的とする Issue では、何を調べ、何が分かれば完了かが伝わればよい。

`ready` は、提案の採用、実装の承認、優先度の高さを意味しない。

## ラベルによるトリアージ

Issue の種類は Type で表し、ラベルは引き渡し可能な状態や、対応を進めるために必要なことを示すために用いる。

| ラベル | 意味 |
| --- | --- |
| `ready` | 他の人に割り当てて取り組んでもらえる程度に整理されている |
| `needs-info` | 必要な情報や説明の補足が必要 |
| `needs-decision` | 方針や要件について人間の判断が必要 |
| `needs-inspection` | 現状の調査や事実確認が必要 |

人間・エージェントのいずれも、状況に応じてラベルを付与・更新してよい。Draft のすべてに `needs-*` を付与する必要はない。

`needs-*` を付与するときは、何の情報・判断・調査が必要なのかを本文またはコメントで分かるようにする。必要な情報や結果が記録され、その必要が解消したら、対応するラベルを外す。

`ready` と `needs-*` は併用してよい。たとえば、調査内容が整理され、他の人に調査を依頼できる Issue には、`ready` と `needs-inspection` を付与できる。ただし、不足や未決事項によって依頼する作業自体が不明確になった場合は、`ready` を外して再整理する。

## レビューとの関係

Issue の作成やラベルの付与は、提案の採用や実装の承認を意味しない。変更に対するレビューの要否および方法は、[レビュー規約](review.md)に従う。
